Análisis de Seguridad — Microsoft Security Envisioning Workshops
=====================================================================

1. Naturaleza del repositorio
------------------------------
Repositorio 100% estático (Office docs + markdown). Sin código ejecutable,
sin dependencias técnicas, sin build, sin tests, sin runtime.

2. Categorías de riesgo evaluadas
----------------------------------
- Autenticación y control de acceso: No aplica (sin código, sin API, sin endpoints)
- Validación de entradas: No aplica (sin entradas de usuario)
- Exposición de datos sensibles/secretos: Ver Hallazgos 2 y 4
- Uso inseguro de rutas/parsing/escritura: No aplica (sin código)
- Dependencias con riesgos: No existen dependencias técnicas
- Abuso lógico/ejecución no controlada: Ver Hallazgo 1 (prompt injection sobre el agente AI)
- Riesgos operativos/configuración/arquitectura: Ver Hallazgos 3 y 5

3. Hallazgos clave
-------------------

A) VECTOR DE INYECCIÓN DE PROMPT (Alta)
   README.md es el system prompt del agente AI. Cualquier modificación
   maliciosa puede redefinir su comportamiento. Sin controles de integridad.

B) EXPOSICIÓN FUTURA DE PII (Media/Alta)
   Los entregables en Entregables_SesionN/ están diseñados para contener
   datos de cliente. Si un cliente real se documenta aquí, es exposición
   de datos sensibles en el repositorio.

C) DUPLICACIÓN DE INSTRUCCIONES (Baja — RESUELTO)
   AGENTS.md existe solo en raíz. No hay copia en docs/. Verificado en Fase 1.

D) URLS CON RUTAS INTERNAS (Baja — RESUELTO)
   url.txt: URLs directas de Partner Center Downloads reemplazadas por aka.ms (Fase 1).

E) AUSENCIA DE REVISIÓN (Media)
   Sin branch protection, sin PRs, sin CI/CD. Cualquier cambio se
   incorpora sin validación.

F) SUPERFICIE DE ATAQUE MÍNIMA (Fortaleza)
   Sin código ejecutable = sin vectores clásicos (RCE, inyección, path
   traversal, SSRF, XSS, deserialización, etc.).

4. Conclusión
--------------
El riesgo principal de este repositorio no está en el código (no lo hay),
sino en su uso como fuente de verdad para un agente AI y como almacén
potencial de datos de cliente. Las medidas recomendadas son:
- Hash/checksum sobre README.md para detectar manipulaciones
- Branch protection + PRs obligatorios
- Sanitización de datos de cliente antes de commit
- ~~Eliminación de duplicados~~ (no existían en working tree; verificado en Fase 1)
