Análisis de Arquitectura — Microsoft Security Envisioning Workshops
=====================================================================

1. Propósito real
------------------
NO es una aplicación. Es un kit de contenidos estáticos (Office docs + markdown) para que un formador imparta 4 talleres oficiales de seguridad de Microsoft. El README.md es en realidad un system prompt que define el rol de un agente AI que automatiza la preparación de guiones y análisis de esos talleres.

2. Entrypoints principales
---------------------------
- README.md: System prompt del agente AI. No es documentación humana, es instrucciones para una LLM.
- AGENTS.md: Guía del repositorio para el agente. Convenciones, estructura, git.
- url.txt: URLs oficiales de descarga de los kits Microsoft en Partner Center.
- docs/Talleres_Ciberseguridad_DataSecurity_ThreatProtection.docx: Documento Office movido desde raíz a docs/ (Fase 1). Sin referencias en ningún flujo.

3. Flujo de ejecución
----------------------
No existe flujo de ejecución. No hay código, scripts, tests, ni build. El flujo es enteramente manual: el formador pide al agente AI preparar un taller, y el agente genera markdowns dentro de Entregables_SesionN/. Lo único ejecutable conceptualmente son los 5 entregables generados hasta ahora:

- Cloud Security/Entregables_Sesion1/ — 2 archivos (guion + notas orador)
- Data Security/Entregables_Sesion4/ — 1 archivo (análisis brechas + CFO)
- Threat Protection/Entregables_Sesion1/ — 2 archivos (guion + notas)

Modern SecOps no tiene ningún entregable generado aún.

4. Módulos (directorios) y su responsabilidad
----------------------------------------------
- Cloud Security Envisioning Workshop/: Contenido del taller Defender for Cloud, CSPM, multi-cloud (10 archivos Office numerados 00-10 + 1 entregable)
- Data Security Envisioning Workshop/: Contenido del taller Purview v8.5.x, DLP, IRM (24 archivos numerados DS-00 a DS-90 + 1 entregable)
- Modern SecOps Envisioning Workshop/: Contenido del taller Sentinel, SIEM/SOAR (11 archivos numerados 00-13, sin entregables aún)
- Threat Protection Envisioning Workshop/: Contenido del taller Defender XDR, Entra ID (12 archivos numerados 00-13 + 1 entregable)
- docs/: 6 subdirectorios con contenido propio (architecture, executive, implementation, raw, roadmap, security). Sin copia de AGENTS.md. Archivos: architecture.md, backlog.md, phase-1.md, progress.md, roadmap.md, security-review.md, executive-summary.md, session-architecture.txt, session-security.txt.

5. Dependencias clave
---------------------
Cero dependencias técnicas. No hay package.json, requirements.txt, Dockerfile, ni nada similar. Las únicas dependencias son del ecosistema Microsoft:
- kits oficiales descargables desde url.txt (Partner Center / aka.ms)
- Microsoft 365 Maps (m365maps.com) y Licensing School (licensingschool.co.uk) — referenciados en README.md como fuentes para estimaciones económicas

6. Limitaciones actuales del diseño
------------------------------------
- Sin automatización real: No hay scripts, pipelines, ni tests. Todo el valor está en la generación manual de markdowns por el agente AI.
- Sin validación de entregables: No hay forma de verificar que los outputs cumplen el esquema de 4 sesiones, el tono español peninsular, o las secciones obligatorias de la Sesión 4.
- docs/ poblado: 6 subdirectorios, todos con contenido. Sin duplicados de AGENTS.md.
- Modern SecOps incompleto: Es el único taller sin ningún entregable generado.
- .gitignore referencia generar_docx.py: archivo que no existe en el repo. Pista de que hubo o se planeó un script de generación DOCX que nunca se materializó.
- Un solo commit, una sola rama: Sin workflow de revisión ni integración continua.
- Nomenclatura unificada: Threat Protection renombrado de Entregables_Sesion1_Kickoff/ a Entregables_Sesion1/ (Fase 1). Todos los talleres siguen la convención Entregables_SesionN/.
